# LaTeX Codex

In **选字 / Select text** mode, starting a left-button drag on a blank PDF page area (without the text cursor) draws a rectangular selection on that page. Starting on the text cursor retains ordinary browser selection. The box gathers glyphs by their PDF positions, including fraction rows and scripts, and highlights them after release. Glyph data is read lazily and cached per page of the displayed PDF; moving the pointer does not read glyphs or call SyncTeX. Right-click the selection for **添加批注 / Add comment**, using the existing source matching flow. Display formulas prefer verified compiled geometry and select the complete math environment; literal matches inside inline formulas also expand to the complete expression. Boxed prose requires a unique literal or supported projected-text match and cannot use edit-distance guesses across omitted words. If the box selects disconnected prose fragments, enlarge it to include the intervening text or select directly in source. Ctrl+C copies extracted PDF text in PDF content order, which is not guaranteed to be mathematical reading order. Esc, mode changes, zoom, PDF replacement or leaving the browser clears the box. Captured drags are clamped to the starting page; ordinary text drags still support multiple pages. A source/PDF change during asynchronous extraction or later mapping invalidates the selection.

Explicit invocation: `$latex-codex 打开 <path/to/file.tex>` opens the requested file in this plugin's local browser editor and compiles with the installed TeX engine. Resolve relative document paths from the user's current project directory, not the skill directory. Treat the path as a document argument, not shell code. If the host picker shows plugin-qualified skills, select `latex-codex:latex-codex`. This is an open request: preserve the document's existing content and follow the launch steps below.

When the user or project instructions choose LaTeX Codex as the default, follow this workflow after creating or editing a `.tex` document without requiring another plugin mention. Open the local server URL with a browser target, and use its local TeX compilation. Reuse a server started for this document in the current chat; external edits synchronize through the existing editor flow. Do not use the native file target or `compile_latex_document` for this chosen workflow. Report missing local dependencies without silently switching compilers. This preference guides the agent; it does not register a replacement for the app's native file preview.

The **PDF 改动 / PDF changes** history tab compares the same selected versions as the source diff. It loads cached before/after PNG crops for this exact source comparison, or compiles the entry-file snapshots into isolated temporary directories and reads each compiled SyncTeX file once into a source-line index to crop the PDF regions associated with changed source lines (unrecognized formats fall back to the SyncTeX CLI), and shows only the after crop by default, with complete changed PDF sentences tinted red, including their inline formulas. Unchanged sentences in the same paragraph retain their original colors; deleting words marks the surviving sentence, while deleting a whole sentence does not mark the next one. A square icon with a dashed divider and one dashed side in each card’s top-right corner toggles between the original before crop and the marked after crop. The toggle is inset from the sidebar edge, and the After label is red. PDF history browsing disables text selection and native image dragging so rapid toggle clicks only switch the displayed side; source history views remain selectable. The marking affects preview pixels only and never writes color commands into source. PDF text positions come from the bundled PDF.js glyph stream in TeX content order. The browser reads page MediaBoxes and exact glyph advances, then sends validated geometry bound to the compiled PDF hash for history matching; no Poppler tools are required. Consecutive small margin line numbers are excluded, sentences are compared after normalizing line-end hyphenation, and common academic abbreviations stay within their sentence. Both before and after crops are rebuilt from complete changed PDF sentences with small vertical margins; unchanged sentences in a long source line do not expand the crop. A changed sentence or formula spanning pages keeps separate page crops together in one card. Formatting-only changes retain their direct source-line crop. Edits separated only by an unchanged display equation within one paragraph share a card; blank lines, section headings, list items and non-math environments (including theorems and proofs) keep independent blocks separate. History PDF generation uses its own lock, so it does not block live state polling or saves; state polling keeps only one request in flight. Switching versions/views or closing the dialog aborts the old browser request and cancels its backend comparison between compilation/rendering stages, so obsolete comparisons do not accumulate in the queue. Later pagination or reflow does not produce extra change cards. Cross-page regions remain separate crops within the same change. Insertions/deletions show an empty counterpart; unmapped source commands show a source-comparison hint instead of a whole-page diff. This does not save, restore, compile over, or replace the live source/PDF, and switching views/versions or closing ignores stale results and destroys PDF workers. Only browsing PDF changes saves images: after both sides have rendered, the browser archives each crop as a 1400px-wide PNG, including the red sentence marks, in `.latex-codex/pdf-diff-cache/`. Cross-page edits retain one image per page; additions/deletions and unmapped source keep their empty-side hints. Later visits load these paired images directly without TeX compilation or PDF.js rendering, including after a restart. The **重新编译 / Recompile** button bypasses the image cache, rebuilds both versions and replaces the comparison images only after successful rendering. Ordinary live compilation never archives full PDFs or SyncTeX. Four temporary compiled snapshots remain until eviction or server exit. This disposable image cache retains up to 256 MiB per project; archives unused for 30 days are pruned during reads/writes. Deleting it is safe: missing or damaged previews are regenerated on demand. Cache save failures leave the visible comparison and source intact and report the error. The old `.latex-codex/pdf-cache/` directory is unused and can be deleted. Permanent history stores each opened source separately: historical child sources are overlaid in a temporary project tree and compiled through the main file; the other sources, images and bibliography are read from the current project when rebuilding an old version; unavailable or invalid dependencies show a compilation error while source history remains usable.

This is a local browser panel, not a new native sidebar extension. In **选字 / Select text** mode, select PDF text and right-click for **在侧边聊天中提问 / Ask in side chat** or **添加批注 / Add comment**. Both use the existing matching flow: SyncTeX maps the first and last selected glyph rectangles to nearby source, then the selected PDF text is matched to a unique source range before opening either composer, preferring an exact literal match. Only that text is selected; neighboring paragraph text is excluded. The status bar shows the selected source line range. Reverse drags and cross-page selections use the PDF text layer's document order and each page's viewport transform. Nearby paragraph boundaries limit the matching search, never the final selection. Whitespace, nonbreaking spaces, common ligatures and line-end hyphenation are normalized while retaining original source offsets. If literal matching fails, bundled KaTeX projects supported formulas to visible MathML text using literal macro declarations from the main file preamble (also when selecting an included source), and common leaf formatting commands to their contents while retaining source offsets. Macro declarations use the same bounded parser as instant formula previews; unsupported declarations and unknown macros remain matching barriers. Formula or formatting boundaries expand to the intact source expression, never the whole paragraph. A bounded edit-distance match tolerates glyph substitutions and reordered formula scripts with up to 20% edits, rejecting equally good source ranges or unbalanced groups. Complete math environments are included when a SyncTeX endpoint lands in their body. Consecutive smaller numbers beside prose identify PDF margin line numbers; those are excluded from both text matching and endpoint lookup while numbers inside formulas and tables remain. The current successful build's auxiliary label values supply rendered equation numbers and `\ref` / `\eqref` text. Numeric BibTeX/natbib citation values also project plain `\cite` / `\citep` commands to PDF brackets (including multiple keys in source order), preserving the complete source macro when selected. If rendered citation matching fails, plain numeric PDF brackets and source citation macros become corresponding placeholders. A unique surrounding prose match (at least 32 Latin letters) then locates the source without needing bibliography numbers, preserving complete citation macros and the actual selected edges, including a previous word or next initial. This fallback tolerates at most 5% edits, capped at 12 characters, and rejects equally good ranges. Citation-only selections still require compiled labels. Citation notes, author-year and custom citation styles remain unsupported; other unknown macros stay matching barriers. Numbered math environments render without numbering in KaTeX while their compiled label numbers participate in matching; labels are ignored by the math renderer. Failed builds and file switches cannot reuse old reference or citation metadata. Approximate matches are identified in the status bar. Unsupported macros, missing or ambiguous matches require manual source selection without changing the existing selection. The prompt includes exactly the matched LaTeX slice. The full panel previews the selection and requires Apply for replacements; comment batches apply their independent replacements only after the top Send action. An included-file mapping first opens the matching project source, then matches the exact selection there. A changed source/PDF build, compilation conflict or selection spanning multiple source files rejects the selection without editing it. Shift+right-click, empty selections and pan mode keep the native menu. No model request is sent until the user submits a side-chat question or clicks the top Send button for comments.

The editor uses a project root and a fixed main compilation file. The root defaults to the main file’s directory; **文件 → 项目设置 / File → Project settings** accepts another folder and a main file (absolute or relative to that folder). The source dropdown lists project `.tex` files by relative path. Editing a child source saves that file and compiles the main document; TeX paths are still resolved from the main file’s directory. Forward navigation uses the active source, and inverse navigation automatically opens the matching project source without replacing the main PDF. Opening an included source with the file picker keeps the project; opening another standalone document starts its own project. Missing TeX dependencies should be reported rather than installed automatically.
