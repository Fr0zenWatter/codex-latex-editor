# LaTeX 版本时间线设计

时间线用于查看入口 `.tex` 文件的修改过程、比较版本并恢复旧内容。当前设计的核心是：保留已捕获的源码快照，在界面上合并密集的自动记录，恢复前先备份当前内容。本文总结截至 2026 年 10 月 2 日的仓库实现。

## 界面与浏览

工具栏的“历史”按钮打开版本历史弹窗。左侧展示源码或 PDF 改动，右侧按新到旧排列版本，顶部提供刷新和对比目标，底部提供恢复操作。时间使用浏览器本地时区显示；版本标题优先使用用户名称，否则显示记录类型。

选中一个版本后，可以切换“改动对比”“PDF 改动”和“此版本源码”。浏览历史只更新弹窗，不替换编辑器内容。刷新时重新捕获当前文件、编辑内容和文件版本；切换文件会关闭历史弹窗。异步读取使用请求序号，避免旧响应覆盖新选择。

## 快照记录与存储

历史保存在入口文件所在目录的 `.latex-codex/history.sqlite3`。同目录的文件共用数据库，源码记录按文件名隔离。每条记录包含版本编号、文件名、UTC 时间、类型、名称、内容摘要和压缩后的完整源码。

源码快照追加写入，已有快照的源码不修改；名称可以修改。内容以 SHA256 摘要与该文件最新快照比较，相同则复用最新版本编号，避免重复记录。源码用 zlib 压缩，不依赖额外数据库服务。

| 类型 | 记录时机 | 时间线显示 |
| --- | --- | --- |
| `open` | 打开文件时记录其内容，仍受内容去重规则约束 | 独立节点 |
| `save` | 自动保存或编译前保存源码 | 未命名时参与合并 |
| `external` | 读取状态、打开历史或写入前发现磁盘内容变化 | 未命名时参与合并 |
| `before-restore` | 恢复前记录传入的编辑器草稿，仍受内容去重规则约束 | 独立节点 |
| `restore` | 写入所选旧版本后记录恢复结果，强制生成新记录 | 独立节点 |

保存与编译分开处理：先保存源码并记录历史，再编译。因此编译失败的内容也能在历史中找回。外部修改在读取或保存时被发现并记录，不保证捕获两次读取之间的所有中间内容。

## 五分钟合并与命名版本

五分钟规则作用于列表查询，底层快照不会被合并、覆盖或删除。具体规则是：

1. 将时间按 UTC 时间戳划入固定的 300 秒窗口。
2. 对同一窗口、同一检查点区段内未命名的 `save` 和 `external`，只显示编号最大的记录。
3. 非自动类型的记录以及有名称的记录单独显示，并形成检查点边界，阻止前后自动记录跨边界合并。

例如，12:01、12:02、12:04 的普通记录在没有检查点隔开的情况下，只显示 12:04。给 12:02 命名后，它将前后记录分为两个区段，12:01、12:02、12:04 分别显示。无论如何显示，三份源码快照都保存在数据库中。这是显示分组，不是每五分钟才保存一次。

版本名称输入最多 120 个字符，保存时去除首尾空白。命名只更新名称，不生成新的源码快照。清除普通自动记录的名称后，该记录重新参与显示合并。

列表每次返回最多 100 个可见版本，通过版本编号游标加载更早记录。先对完整历史计算分组，再筛选游标，避免翻页时把被隐藏的快照重新显示出来。“上一版”同样按可见节点查找，使比较覆盖一段编辑过程。

## 源码与 PDF 对比

| 对比目标 | 比较方向与含义 |
| --- | --- |
| 与上一版比较 | 上一个可见版本 → 所选版本；最早版本与自身比较 |
| 当前编辑内容 | 所选版本 → 打开或刷新历史时捕获的编辑内容，包含未保存修改 |
| 指定历史版本 | 所选版本 → 已加载列表中的指定版本 |

“当前编辑内容”是一次捕获的快照，后续变化需要刷新历史才能纳入对比。

源码对比先按行匹配，再对替换部分细分为词、LaTeX 命令、中文字符等片段。未变化内容保留，新增内容着色，删除内容加删除线；行号以比较后的源码为准，纯删除行显示减号。下方还有改动时提供跳转按钮，方便浏览长文档。

PDF 对比按需生成，不预先保存每个历史版本的 PDF：

1. 在临时目录中分别编译比较前后的入口源码，使用项目当前的图片、引用文件和参考文献等依赖。
2. 从源码行差异得到改动范围，再用 SyncTeX 定位对应 PDF 区域，按页裁剪改动附近的内容。后续页面仅因排版移动而变化时，不额外生成改动卡片。
3. 用 Poppler 的 `pdftotext` 提取文字与坐标，比较前后文字并归一化换行连字符，在修改后的预览中将新增或替换文字标红。
4. 每张卡片默认展示修改后内容，可切换查看修改前内容。纯新增、纯删除或无法对应 PDF 内容时显示文字说明。

历史编译不写回当前入口文件，也不替换编辑器的实时 PDF。已编译快照按文件路径和源码摘要缓存，最多保留 4 份；淘汰或服务退出时清理临时目录。编译、定位或文字提取失败时，弹窗显示错误，用户仍可查看源码对比。

## 恢复与冲突保护

恢复必须经过“恢复此版本”和“确认恢复”两步。确认时传入所选版本编号，以及打开或刷新历史时捕获的文件路径、编辑器草稿和文件版本。

恢复流程为：

1. 前端确认编辑器内容和文件版本仍与捕获状态一致，并临时停止编辑及自动保存。
2. 后端校验当前文件和版本归属，先记录磁盘上的当前内容，再检查文件版本是否冲突。
3. 记录传入的未保存草稿；备份失败时停止恢复。
4. 将旧源码写入同目录临时文件，再次检查磁盘版本，使用 `os.replace` 替换入口文件。
5. 追加 `restore` 节点，更新编辑器，关闭历史弹窗并重新编译。

恢复会成为时间线上的新节点，所选版本之后的历史仍然保留。前端内容发生变化或后端发现文件冲突时拒绝恢复，要求刷新或处理冲突。重新编译失败不会撤销已完成的源码恢复。

## 实现入口与边界

| 文件 | 负责内容 |
| --- | --- |
| [history.py](../plugins/latex-codex/scripts/history.py) | SQLite 存储、去重、显示分组、分页、命名和源码差异 |
| [editor.py](../plugins/latex-codex/scripts/editor.py) | 保存与恢复、历史接口、历史 PDF 编译和定位 |
| [latex-history.mjs](../plugins/latex-codex/scripts/vendor/latex-history.mjs) | 弹窗交互、版本选择、源码展示、PDF 卡片和请求失效处理 |
| [latex-history.css](../plugins/latex-codex/scripts/vendor/latex-history.css) | 历史弹窗布局、改动样式和窄屏适配 |

当前只保存入口文件源码，没有整个项目的历史快照。历史 PDF 使用当前依赖重新编译，不能保证复现当时的完整输出；缓存键也不包含依赖内容，依赖单独变化时可能复用已有编译结果。PDF 定位与标红依赖 SyncTeX 和可提取文字，不能覆盖所有图片、公式或间接宏展开造成的视觉变化。

当前没有分支、多人作者记录或自动清理历史的策略；时间线是本地文件恢复工具。数据库位于文档旁，已由仓库 `.gitignore` 排除，不应提交。

已有检查分别位于 [test_history.py](../plugins/latex-codex/scripts/test_history.py)、[test_history_ui.mjs](../plugins/latex-codex/scripts/test_history_ui.mjs) 和 [test_history_pdf.py](../plugins/latex-codex/scripts/test_history_pdf.py)，覆盖分组与分页、快照保留、草稿备份、冲突保护、过期响应，以及历史 PDF 的局部对比和当前文档保护。
