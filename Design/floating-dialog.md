# 悬浮对话框设计

悬浮对话框用于在编辑现场输入问题或修改指令，让用户保持对正文和选区的关注。视觉参考来自提供的 `ai-chat-input.tsx` 中的 `PromptInput`：空闲时是紧凑的胶囊形输入入口，使用时展开为多行卡片，模型设置、附件和语音按状态出现。

本文分别记录参考组件的设计和项目现有的选区悬浮对话行为。参考组件本身使用相对布局，放置位置由宿主决定；示例将它居中展示。跟随选区定位和拖动属于当前项目已有行为。

## 输入卡片与信息层级

主卡片由输入区、底部工具栏和右下主操作组成。收起时只显示占位提示与主操作按钮；展开时输入区占据上方，底部从左到右排列模型、思考等级和附件入口。发送按钮始终保持在右下位置。

卡片使用主题提供的背景、文字、边框和主色，细边框配轻微阴影。获得焦点时增强边框并出现浅色焦点环。示例页面的彩色渐变是展示背景，卡片可独立放到编辑器中。

| 属性 | 参考组件中的值 |
| --- | --- |
| 收起尺寸 | 最大宽度 320 px，高度 48 px |
| 展开宽度 | 最大宽度 480 px，实际宽度受宿主容器限制 |
| 主卡片圆角 | 24 px |
| 展开输入区 | 高度 68–160 px，超过上限后内部滚动 |
| 展开主卡片高度 | 输入区高度加 48 px，即 116–208 px |
| 输入文字 | 14 px，行高 22 px |
| 输入左右留白 | 左侧 16 px，右侧 48 px，为主操作预留空间 |
| 主操作按钮 | 32 × 32 px，圆形，距右边和底边各 8 px |
| 附件入口按钮 | 28 × 28 px |
| 附件托盘 | 独立占据卡片上方 68 px，高度不计入主卡片 |
| 附件缩略图 | 48 × 48 px，圆角 12 px |

文本滚动时，上下边缘以渐变提示仍有内容。滚动条保持细窄，悬停时增加可见度，避免输入区域产生明显的视觉分隔。

## 展开与操作状态

| 状态 | 卡片表现 | 右下主操作 |
| --- | --- | --- |
| 空闲收起 | 胶囊形入口，显示占位提示 | 麦克风，启动语音输入 |
| 展开但内容为空 | 显示多行输入区与工具栏 | 麦克风 |
| 有非空文本或附件 | 保持展开，可提交当前内容 | 上箭头，发送 |
| 正在录音 | 保持展开，隐藏底部工具栏，显示五条音量柱，文本框不可手动编辑 | 方形图标，停止录音 |
| 模型菜单打开 | 当前卡片上方出现模型列表 | 保持当前状态 |
| 图片预览打开 | 缩略图放大到视口中央，出现遮罩 | 由预览关闭操作控制 |

点击占位入口会展开并聚焦输入框，光标移动到文字末尾。已有文字或附件时也会自动展开。焦点转移到组件内部控件时保持展开；焦点离开且没有文字、附件和录音时收起，保留有内容的草稿。

参考组件使用 Enter 提交、Shift+Enter 换行；输入为空且没有附件时，Escape 可以收起。提交通过 `onSubmit` 传出文本、模型、思考等级和原始附件文件，随后请求清空输入、清理附件并收起。

这里的方形图标表示停止录音。参考组件没有请求等待、生成中、失败重试或停止 AI 生成的状态；这些状态需要接入真实请求流程后定义。

## 模型与思考等级

模型按钮以小图标和名称组成，点击后在其上方展开菜单。菜单使用圆角、细边框、半透明背景、模糊和较明显的阴影，与主卡片保持同一视觉语言。悬停背景跟随条目移动，选择后更新名称并关闭菜单；点击组件外部也关闭模型菜单。

名称变化时，文字容器宽度平滑调整，同时淡入新名称，避免工具栏突然跳动。思考等级通过点击循环切换，三段柱形图以亮暗变化表达 Low、Medium、Max Effort。

模型与等级列表由参数提供。参考代码中的模型名称和图标属于示例数据，不能据此认定当前 Codex 支持这些模型或等级。项目复用时应沿用真实模型能力列表，以及“跟随默认”的选择。

## 图片附件与放大预览

附件托盘从输入卡片背后向上出现，两侧内缩，让主卡片仍是视觉主体。缩略图横向排列，空间不足时横向滚动；添加附件只改变托盘，文本高度继续由输入内容决定。

参考组件只接收图片，默认附件上限为 6。缩略图悬停时轻微放大并出现删除入口，点击缩略图打开大图。提交时传递原始 `File` 对象，缩略图使用本地对象 URL。

大图保留图片比例，目标尺寸同时受视口宽度的 86%、视口高度的 78%、560 px 宽和 720 px 高限制，放大比例最多为原图的 1.6 倍。打开时从缩略图的位置与尺寸过渡到居中大图，圆角从 12 px 变为 20 px；关闭时回到原位置。点击遮罩、关闭按钮或 Escape 均可关闭。

预览遮罩使用半透明背景与模糊，卡片本身仍是轻量输入区域。当前项目尚未接入这套图片附件和预览功能。

## 语音输入

空内容时点击麦克风进入录音状态，按钮切换为停止，旁边显示五条随音量变化的竖柱。参考组件用 Web Audio 获取音量，用浏览器 Speech Recognition 将识别结果写入文本，并在录音过程中滚动到输入末尾。

参考代码在麦克风不可用或缺少语音识别能力时，会生成模拟波形或预设文本，这是演示行为。实际产品应显示不可用原因并保留手动输入。停止录音只结束采集，识别文字留在输入框中，用户再决定发送。当前项目没有语音输入能力。

## 动画节奏

| 变化 | 参考时长与方式 |
| --- | --- |
| 收起与展开 | 约 400 ms，尺寸变化使用带回弹的缓动曲线 |
| 打字引起的高度变化 | 约 150 ms，使用 ease-out，避免每次输入都明显弹跳 |
| 模型名称变化 | 约 300 ms，宽度调整与淡入缩放 |
| 主按钮图标切换 | 约 300 ms，组合淡入、缩放、少量旋转和模糊 |
| 附件入场 | 约 400 ms，每项错开 35 ms |
| 图片预览打开 | 约 450 ms，从缩略图位置展开 |
| 图片预览关闭 | 约 300 ms，回到缩略图位置 |

动画主要由 CSS transition 和关键帧类完成，没有使用 Framer Motion。复用时应支持减少动态效果的系统偏好，并让菜单、预览和发送操作在关闭动画时仍然正常工作。

## 当前项目的选区悬浮对话

现有悬浮对话位于 [editor.py](../plugins/latex-codex/scripts/editor.py) 和 [latex-chat.mjs](../plugins/latex-codex/scripts/vendor/latex-chat.mjs)。它使用原生 `popover`，空闲时为 320 × 48 px 胶囊，聚焦后最多展开为 480 px 卡片、圆角 24 px，输入高度自适应为 68–160 px；背景、边框、文字与发送按钮随当前主题变化；发送中按钮显示加载指示，输入只读，模型入口暂时禁用。

当前产品行为包括：

- 从源码或 PDF 选区菜单打开；PDF 选区先映射到 LaTeX 源码，再捕获对应内容。
- 优先放在选区下方，空间不足时放到上方，位置限制在视口内并保留 8 px 边距。
- 顶部拖动区域支持指针捕获；键盘方向键每次移动 10 px，窗口尺寸变化后重新限制位置。拖动时保留输入草稿和选区。
- 与侧边聊天共享真实模型、思考等级和项目对话记忆；使用 Ctrl+Enter 或 Cmd+Enter 发送，并避开输入法组合中的 Enter。
- 发送前检查捕获的文档和选区内容。收到修改结果后再次检查，只有原选区仍有效、内容未变化且编辑器允许编辑时才自动应用；应用后自动保存，可通过编辑器撤销。
- 纯解释在悬浮框内显示；请求失败时保留问题以便重试。关闭正在请求的悬浮框会取消任务，过期结果不会应用到文档。

已有 [test_chat_ui.mjs](../plugins/latex-codex/scripts/test_chat_ui.mjs) 覆盖选区定位、拖动与边界、模型设置、加载状态、取消、错误显示和旧选区保护。

## 复用范围与实现要求

建议优先将参考组件的胶囊展开、多行自适应和工具栏层级用于当前悬浮框，同时保留已有定位、拖动、请求取消和修改保护。键盘发送继续采用当前快捷键，多行输入使用普通 Enter；语音与附件在相应后端能力可用时再加入。

交互控件需要明确的可访问名称、键盘焦点和状态。图片删除应使用独立可聚焦按钮；大图预览打开时管理焦点，关闭后返回来源控件。菜单与浮层应适配视口边缘，输入法组合中的 Enter 不触发提交。异步请求失败时保留草稿，成功后再清空输入。

参考实现使用 React、TypeScript、Tailwind 和动画样式类；这些是它的实现方式。当前项目已有原生 HTML、JavaScript、CSS 和 Popover API，可复用相同视觉与交互。当前已用原生实现接入胶囊展开、多行自适应、底部模型与思考等级工具栏、焦点环和减少动态效果支持。没有引入新框架或依赖；附件与语音仍未接入。
